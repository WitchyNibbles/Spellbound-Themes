# WitchyNibbles icon assets

The file icon theme is built from the drawing-based map in `file-icon-map.json`: each drawing is written as code in `scripts/file-glyphs/` with colour-role tokens instead of hex values (`npm run draw:file-icons` regenerates the sources in `file-src/`; the tests fail if a committed source drifts from its generator), and the map lists each drawing's category and the file extensions, file names, folder names and language IDs it serves. `npm run build:file-icons` resolves every source into the dark, light and high-contrast sets in `file-icons/` (colours from `scripts/lib/file-icon-palette.mjs`) and regenerates `file-icon-theme.json`; do not edit either by hand. `npm run file-icon-sheet` renders every drawing for review.

The product icon theme is built from the drawing-based map in `product-icon-map.json`: each drawing has one SVG in `product-src/`, one private-use codepoint, and the list of VS Code icon IDs that use it. Drawings are written as code in `scripts/glyphs/` (`npm run draw:glyphs` regenerates the SVGs; the tests fail if a committed SVG drifts from its generator). `node scripts/claim-drawing.mjs <drawing> <codepoint> <id…>` assigns IDs, and `npm run build:product-icons` regenerates `product-icon-theme.json` and `witchynibbles-product-icons.woff`. `product-icon-ids.json` pins the VS Code 1.141 keys the theme must cover. A review gate that compares alternative drawings puts them in `product-src-variants/` (it is not in the repository when no gate needs one); they never enter the font.

These product glyphs were drawn for this extension. They do not use the VS Code Codicons font. Product icon themes are monochrome; VS Code applies the active color theme to them.
