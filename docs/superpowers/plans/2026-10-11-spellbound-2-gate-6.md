# Spellbound Themes 2.0, Gate 5 to Review Gate 6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take the repo from the approved review gate 5 (commit `9536182`, decisions G41-G47) to review gate 6: draw the remaining file icons of spec 6 in four batches (code and style; data and config; docs, assets and tests; folders), 26 file drawings and 14 badged folders closed and open (54 new drawings, 63 in all), map every key spec 6 lists, enforce the `file-icons` validation stage (full key coverage, including the seven `languageIds` still missing), judge the whole set together, generate the gate-6 job (the gate-5 scenes over the whole fixture, with Explorer pages that walk the full tree), and produce the gate-6 evidence in real VS Code 1.141. Then stop for the author.

**Architecture:** Gate 6 adds drawings to the gate-5 pipeline and changes none of it. Drawings stay code in `scripts/file-glyphs/`, one module per category: `code.mjs`, `data.mjs`, `docs.mjs` and `folders.mjs` grow, and four modules are new (`style.mjs`, `config.mjs`, `assets.mjs`, `tests.mjs`), so `fileGlyphModules` ends as `[defaults, folders, code, style, data, config, docs, assets, tests]`. Every drawing is `painted(role, …)` parts written by `fileIconDocument` (`scripts/file-glyphs/parts.mjs`) from the section-4 primitives (`scripts/glyphs/primitives.mjs`) and the gate-2 `parts.star`/`parts.flame` (`scripts/glyphs/batch-1.mjs`); badged folders use `folderBody({ badge: true })`/`folderBody({ open: true, badge: true })` and `BADGE_BOX`. Three file drawings are approved product glyphs split into outline and accent (the quill, the owl, the flask), and a test fails if they stop matching the product ink. `icons/file-icon-map.json` grows in module order; `npm run draw:file-icons` and `npm run build:file-icons` regenerate the sources, the three resolved sets and the theme. `scripts/validation-stage.json` gains `file-icons` once the last batch lands. The gate-6 job is generated by `scripts/review/gate-6-job.mjs` from page lists (24 scenes over the gate-5 templates) and pinned by `test/review-gate-6.test.mjs`; the gate-5 harness is used unchanged.

### Drawing rules (every drawing task)

- Section 4 and 6.2 in full: the 16-unit grid and 1-unit padding; whole-number edges for every horizontal and vertical edge; 45° diagonals 2 units across horizontally (1.41 across the stroke) and 2:1 bands 1.5 across horizontally (1.34 across); odd diameters on .5 centres, even ones on whole centres; keylines (portrait x2-14, y1-15; landscape x1-15, y2-14; round 14; badges in `BADGE_BOX`, x8-15, y8-15); accents at least 3×3 (dot) or 4×4 (shape); real holes (counter-wound subpaths), at least 2 units except straight 1-unit slots at least 4 long; no gap or sliver under 1 unit; one outline part in the category colour plus one accent part, painted last, which may take another role.
- G42: an accent that is part of the object's silhouette (a fold, a tab, a head, a bow, a set stone, a roll, a lid, a body) may touch its outline; an accent that sits on the object (a crown, a seal, a badge, a label, an inscription, a moon) keeps one full unit. Each drawing test states which (`gap: 0` or `gap: 1`).
- Section 6's logo rule: echo the name, never the logo (no whale for Docker, no `>_` for PowerShell, no React atom).
- Look-alikes differ in silhouette (spec 6's 16px rule): the js, ts and tsx/jsx gems (and the tsconfig gem); the json keyring and the html key; the yaml cairn, the jsonl beads and the db cylinder (the lib books are a folder badge, tested with the badges); plus the pairs this plan adds (the sh and ps1 tablets; the src and lib books, the dist bottle, the cache jar and the tests flask). Silhouette tests compare the ink of the solid subpaths alone, holes ignored, on the 1024-sample grid offset by (0.125, 0.3125).
- Every source passes `fileGlyphProblems` with no error and no warning (the drift test asserts both). Two parts that touch meet only along whole-number horizontal or vertical edges, or overlap. Do not use `knockOut` on a subpath with arcs; knockouts are drawn (the gem-gear's is written out).
- `outlineGap` overflows the call stack on two outlines with thousands of flattened points (the owl's four rings measured together): measure such drawings per pair of subpaths, or by ink, as the owl's test does.
- After changing a drawing: `npm run draw:file-icons`, update its `icons/file-icon-map.json` entry (lower-case keys, map order = module order), `npm run build:file-icons`. Never edit `icons/file-icons/**` or `icons/file-icon-theme.json` by hand.


## Review Focus

The five ways this work is most likely to fail a user that the drawing tests do not catch on their own, and what now pins each:

1. **A file shows the wrong drawing because a less specific key wins.** VS Code takes an exact file name first, then the longest dot-suffix, then a language ID: `package-lock.json` must show the padlock, not the keyring; `tsconfig.json` the gem-gear; `sample.test.ts` the flask, not the cut gem; `.env.local` the vial; `README.md` the open grimoire, not the quill. Pinned by `the most specific key wins for the names spec 6 enumerates: lockfiles, configs, tests, .env variants and the special docs` (Task 8), and by the per-drawing map pins (Tasks 1-7).
2. **A key spec 6 lists falls back to the parchment, or a key it does not list sneaks in.** Pinned by `the gate-6 map serves exactly the keys of spec 6 …` and `the built theme passes the file-icons coverage stage with nothing pending (gate 6, spec 8)` (Task 8), and by the enforced `file-icons` stage (Task 8 Step 3 shows a removed key failing `npm run validate`).
3. **A config badge disappears into its folder.** Config and muted are the same hex in every set (`#A99AB9`, `#735F7D`, `#A99AB9`), so the `.github`, `workflows`, `.claude`, `.venv`, `node_modules` and `cache` badges are the folder's colour and are told apart only by the 1-unit knockout and their silhouette. No test can judge that: Task 7 Step 5 judges it at 100% on every side bar and in grayscale, and the gate README puts it to the author as a decision with the evidence.
4. **The gate opens the wrong file and frames the wrong state.** Quick open ranks recently opened files first, and every theme and scale repeats the scenes: typing `test/.keep` after `tests/.keep` was opened in an earlier theme would focus `tests/.keep`, and the open-folder page would then wait for a folder that never opens. Every gate-6 scene that opens a file hides the rest of the fixture with `files.exclude` (quick open honours it) and turns the quick-open history off, and no open page holds two folders whose names contain one another. Pinned by `the open Explorer pages reveal each folder by opening its child, one match per typed path and quick-open history off, and wait with the tree focused`, `the tab pages open every file drawing gate 6 adds, …` and `every gate-6 quick open types its file, waits for that file's row to be focused, then presses Enter; …` (Task 9), and by the targeted dry run at 200% (Task 9 Step 5).
5. **A drawing passes its tables but does not read, or reads as something else, at 16px.** The risks seen while planning: the compass can read as a letter A, the workflows ring as a plain `o`, the cobweb as a crossed box, the js shard as a second bar. Every drawing task ends with the file-icon sheet procedure, Task 8 judges the whole set side by side, and the README names each risk as a decision.
